# Public trend evidence contract

OV028 supports deployment-configured `mastodon_tags` and `rss_news`; no default source or Facebook trend access is implied. Configure `ONEVOICE_TREND_SOURCES` as JSON, for example an array of `{ "key": "community", "kind": "mastodon_tags", "url": "https://your-approved-instance.example/", "ttlSeconds": 86400 }`. Empty configuration records social/news `unconfigured`, Facebook `unavailable`. Invalid configuration fails before fetching. Operators must select sources whose terms permit their intended use. Public API access does not transfer rights to republish content.

Provider contracts verified 2026-09-12:

- [Mastodon trends API](https://docs.joinmastodon.org/methods/trends/) documents public, unauthenticated `/api/v1/trends/tags`. [Tag entity](https://docs.joinmastodon.org/entities/Tag/) defines daily UNIX-midnight usage/account counts. They describe one instance's hashtag activity, not Facebook engagement, global reach, sentiment or product demand. Empty results are successful and can reflect instance moderation/configuration. Disabled/unavailable instances are failures, not zero activity.
- [RSS 2.0 specification](https://www.rssboard.org/rss-specification) and Atom feeds provide headlines/links/publication metadata. These are news signals with no engagement metrics. Missing or invalid timestamps remain unknown and are ineligible for OV029 freshness. Article bodies, media and descriptions are discarded. XML parsing uses fast-xml-parser with DTD/entity declarations rejected and nesting bounded to 32.
- Public smoke proof reads Mastodon.social and [NASA news RSS](https://www.nasa.gov/news-release/feed/) only when explicitly enabled. [NASA usage guidance](https://www.nasa.gov/nasa-brand-center/images-and-media/) permits factual uses subject to attribution, third-party rights and no implied endorsement. This proof imports headline/link/date metadata only and uses no NASA imagery, marks, article bodies or endorsement. These smoke sources are not enabled application defaults. Other Mastodon instances and feed publishers may impose different terms.

All text is `untrusted_external` data. Never insert it as system/developer instructions or overwrite catalog facts. News expiry is bounded by publication + TTL, so refetching old news cannot rejuvenate it. Social expiry is bounded by metric-day end + TTL and observed time + TTL. Unknown dates remain visible evidence gaps but are excluded by `eligibleEvidence`.

`collectTrends(parseSources(env.ONEVOICE_TREND_SOURCES))` prepares a bounded batch; `createTrendRepository(client).save(orgId, runId, batch)` persists it in one service-only transaction. Retain the exact batch and run UUID across uncertain storage retries: changing a receipt's input is rejected. An RPC deadline cancels waiting, not an already committed database write. There is no cron, general worker hookup, AI execution or outbound send in this slice. OV029/automation integration must supply scheduling, active organization authorization and stable receipts.

The immutable run snapshot contains configuration, capability/status, errors, TTL and exact evidence seen in that run. Observations deduplicate across runs; only their latest seen/expiry can advance, never their content. OV029 reads the latest run for its organization (removed providers are absent), checks TTL at decision time, and freezes run ID + evidence + metrics + expiry into its own audited decision. A failed source never silently carries previous observations forward. Available/empty means the provider responded; it does not imply fresh evidence. No snapshot means ingestion has never run.

Transport is the shared `src/lib/network/public-http.ts` (OV052): HTTPS, public IPv4 DNS pinned per connection, no IP-literal endpoints, IPv6-only hosts fail explicitly, same-origin redirects only, 8-second overall deadline, 512-KiB response, no cookies/auth, compressed responses rejected. Lower caller limits are supported. Metadata links are stored but never fetched by adapters. No source response/error body is logged or returned as an error message.

Run a bounded refresh with `node src/lib/trends/run.mjs --local`. Local mode discovers only the running local Supabase and uses the demo organization. Set `ONEVOICE_TREND_SOURCES` explicitly in the shell; with no sources, the command records an unconfigured snapshot. Without `--local`, explicitly provide `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SECRET_KEY` and `ONEVOICE_ORGANIZATION_ID` through the process environment. The command never loads `.env`. It builds a temporary entrypoint, runs one ingestion with a 25-second outer limit, retries uncertain storage once using the identical receipt/batch, and prints only run ID, capability and source-status counts. Exit 0 means persisted with no source errors (including unconfigured/empty); exit 2 means source failures were persisted; exit 1 means configuration/storage/execution failed. There is no daemon or scheduled refresh.

Reproduce local persistence + concurrent receipt proof with `ONEVOICE_LOCAL_TRENDS_PROOF=1 pnpm exec vitest run src/lib/trends/repository.local.test.ts` (set the environment using your shell). It discovers only the local Supabase URL, uses the fixed local Docker container for cleanup, and never reads `.env`. Ordinary unit tests use fake local fixtures.
